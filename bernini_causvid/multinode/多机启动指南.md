# 多机训练 · 无脑启动指南

> 换了机器后照着这份文档抄命令即可。核心：**只在主节点上跑一条 `launch.sh`，唯一要改的是 worker 的 IP。**

---

## 0. 前提（每台机器都满足，一般已就绪）

- 代码 / conda 环境 / 数据 / 模型权重都在共享盘 `/apdcephfs_hzlf/share_1227201/xinyu/`（CephFS，各机可见）。
- 各机之间 `bond1` 网段（`29.209.x.x`）互通，GPU 走 8×RoCE。
- 主节点能 SSH 到各 worker（首次用 `WORKER_PW` 自动配免密）。

---

## 1. 一键启动（推荐，抄这条）

**在主节点（rank0）机器上、`tmux` 里**执行：

```bash
cd /apdcephfs_hzlf/share_1227201/xinyu/Causal-Forcing

WORKER_PW='新机器的登录密码' \
LOGDIR=/apdcephfs_hzlf/share_1227201/xinyu/Causal-Forcing/runs/bernini_edit_ar/20260702_133519 \
  bash bernini_causvid/multinode/launch.sh 2_stage1_train_ar <新worker的bond1_IP>
```

`launch.sh` 会自动：取本机 `bond1` 作 `MASTER_ADDR` → 配免密 → 组装节点列表 → 拉起训练（rank0 前台，worker 经 SSH 后台）。

---

## 2. 换机器时，只改这些

| 位置 | 改成什么 | 说明 |
|---|---|---|
| `<新worker的bond1_IP>` | 新 rank1 机器的 `bond1` IP | 多台 worker 就空格接多个：`... 2_stage1_train_ar IP1 IP2 IP3` |
| `WORKER_PW='...'` | 新机器登录密码 | **仅首次**配免密要；已免密可**删掉这行** |
| `MASTER_ADDR` | **不用设** | 脚本自动取本机 `bond1` IP（前提：在主节点上跑） |

### 拿某台机器的 bond1 IP

在那台机器上执行：

```bash
ip -o -4 addr show bond1 | awk '{print $4}' | cut -d/ -f1
```

---

## 3. 继续训练 vs 全新训练（二选一）

- **继续现在这个 run**（从最新 checkpoint 续训）：保留 `LOGDIR=...`，默认 `RESUME=auto` 会自动找最新 ckpt。
- **全新训练**：**删掉 `LOGDIR=...` 那行**，自动新建 `runs/bernini_edit_ar/<时间戳>/` 目录。

### 想覆盖训练超参（可选）

用同名环境变量前缀透传即可，例如：

```bash
MAX_ITERS=8000 SAVE_EVERY=200 CONFIG=bernini_causvid/configs/causvid_edit_ar_1.3b_reco_chunk3.yaml \
WORKER_PW='...' \
  bash bernini_causvid/multinode/launch.sh 2_stage1_train_ar <worker_IP>
```

常用：`MAX_ITERS` `SAVE_EVERY` `LOG_EVERY` `RESUME`（`auto`/`none`/具体路径）`SAMPLE_STEPS` `GRAD_ACCUM` `NPROC_PER_NODE`。

## 4. 正式训练前先验连通性（可选但推荐）

把目标名换成 `nccl_test`，其余不变：

```bash
WORKER_PW='...' bash bernini_causvid/multinode/launch.sh nccl_test <worker_IP>
```

看到各 rank 都跑通 all-reduce 即说明多机网络 OK，再启训练。

## 6. 怎么看进度

```bash
# 训练日志（换成你的 LOGDIR）
tail -f /apdcephfs_hzlf/share_1227201/xinyu/Causal-Forcing/runs/bernini_edit_ar/20260702_133519/train.log

# GPU 占用（跑起来后每卡应 ~100% 利用率）
nvidia-smi

# rendezvous 端口是否就绪（主节点上，起来后应能看到监听）
ss -tlnp | grep 29500
```

启动后正常时序：`29500 监听` → worker SSH 连入 → 两节点各 8 个 worker → `train.log` 出现 `world_size=N | distributed=True` → `resumed from ... at step X` → 开始刷 `step` 行。

## 7. 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| worker 日志 `client socket has timed out ... 29500` / `RendezvousConnectionError` | rank0 还没监听 29500 就被 worker 抢连（冷启动竞速），或主节点没起来 | `launch.sh` 里 worker 已内置「等 29500 就绪再启动」；确认在主节点上跑、主节点 torchrun 正常拉起即可 |
| 启动后很久 `nvidia-smi` 显存是 0、CPU≈0，进程卡在 `request_wait_answer`(FUSE) | **CephFS 冷启动**：16 个进程同时从网络盘冷读 conda/torch 依赖，海量 `lstat` 慢 | **正常现象**，耐心等几分钟；显存会从 0 → 建 context → 爬满，然后开训 |
| 上次 `Ctrl+C` 后重启，端口/资源冲突，或有僵停 python | 上次 torchrun agent 被杀但 worker 变孤儿（`PPID=1`）残留 | 重启前清理：`pkill -f train_edit_ar.py`（主节点和各 worker 都清）；确认 `ss -tlnp | grep 29500` 无残留监听 |
| SSH 到 worker 要密码 / 免密没配上 | 首次没带 `WORKER_PW` | 带上 `WORKER_PW='密码'` 重跑 `launch.sh`（幂等，已免密的会跳过） |

### 一键清理（重启前，主节点执行）

```bash
# 清本机
pkill -f train_edit_ar.py; pkill -f torch.distributed.run
# 清 worker（换成实际 worker IP）
ssh <worker_IP> 'pkill -f train_edit_ar.py; pkill -f torch.distributed.run'
```

---

## 8. 已免密时

`launch.sh` 是唯一入口。已配过免密后再次运行**省略 `WORKER_PW` 即可**（脚本检测到免密会自动跳过密码步骤），命令其余部分不变。

---

## 关键事实速记

- **全局 batch = per-gpu micro-batch × 卡数 × grad_accum**。当前 config `batch_size: 1` × 16 卡 × 1 = **global batch 16**（与之前单机 8 卡 × micro-batch 2 一致，换机器不用改 lr）。
- 16 卡相比单机 8 卡，速度约 715s/10it → 361s/10it。
- 主节点通信端口固定 `29500`；多机用**静态 rendezvous**（`--master_addr/--master_port + --node_rank`），不用 c10d 动态集合点，也不需要 rendezvous ID。

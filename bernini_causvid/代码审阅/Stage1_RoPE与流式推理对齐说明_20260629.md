# Stage1 编辑模型：mask / RoPE / 流式推理 对齐说明

> 生成日期：2026-06-29
> 范围：`train_edit_ar.py`（Stage1 AR teacher-forcing 编辑扩散）涉及的注意力 mask、
> RoPE、以及 teacher-forcing 训练 ↔ 流式推理的对应关系。
> 方法：逐行读源码 + 独立脚本数值求值（非凭经验）。
> 配置：`causvid_edit_ar_1.3b_reco.yaml`，`num_frame_per_block: 1`（逐帧），
> latent 几何 `[1, 21, 16, 60, 104]`，frame_seqlen = 30×52 = 1560。

---

## 0. 一句话结论

- **mask 正确**：teacher-forcing 下 target 帧 i 只看 source 帧 ≤ i（streamed-causal），无未来泄漏。
- **RoPE 正确**：dense 训练与流式推理的位置/source_id 几何逐位一致；source 帧 i ↔ target 帧 i 同位置。
- **推理无 target gt 不影响 RoPE**：训练的 clean(gt) 流在推理时由 target KV-cache（模型自生成 + context refresh）顶替，写入时按相同 RoPE 位置（帧号、source_id=0）。
- 目前唯一无法在本仓库内验证的：`visual_id_freqs` 是否与 Bernini 原始推理逐位 parity（Bernini 源码不在本仓库）。

## 1. token 三段与 mask（训练）

teacher-forcing 序列：`[ source | refs | clean target(gt) | noisy target ]`。
走的是 `causal_edit_model.py::_prepare_edit_tf_attn_mask`（由 `forward_edit` 在
`clean_target is not None` 时选择；`causal_source=True` 恒定 → `src_mask_len=src_len`）。

可见性（已数值验证，nfpb=1 即逐帧）：

| query | 能看到的 key |
|---|---|
| refs | refs（全局 prefix） |
| source 帧 i | refs + source ≤ i（块内因果） |
| clean(gt) 帧 i | refs + source ≤ i + clean ≤ i |
| noisy 帧 i | refs + source ≤ i + clean **< i**（严格更早） + 自身 noisy 帧 i |

关键行 `allow_src = kv_src & (kv_idx < src_vis_end[q_idx])`，target 帧 i 的
`src_vis_end = min((i+1)*attn_block, src_len)` → source 帧 ≤ i。

数值验证（缩小 frame_seqlen 便于打印）：

```
frame 0: clean sees src [0]            | noisy sees src [0]
frame 1: clean sees src [0,1]          | noisy sees src [0,1]
...
frame 5: clean sees src [0,1,2,3,4,5]  | noisy sees src [0,1,2,3,4,5]
```

> 注意：clean 帧 i 和 noisy 帧 i 占**相同位置 i**，但 mask 保证 noisy i 只看 clean **< i**，
> 不看同位置的 clean i 本身（否则等于抄答案）。

## 2. RoPE 细节

### 2.1 位置 RoPE 表
`self.freqs` = 三段 `rope_params(1024, …)` 拼接 → **[1024, 64] complex**，按 `[22,21,21]`
切 t/h/w（head_dim=128, c=64）。dense `_rope_region` / 流式 `_causal_edit_rope_apply`
对位置部分与框架 `rope_apply` / `causal_rope_apply` 逐位相同。

### 2.2 source_id RoPE（编辑增量）
`from_causal_model` 用 `get_1d_rotary_pos_embed(head_dim=128, 1024, theta=10000)`
得到 **[1024,64] complex** 表 `_visual_id_freqs`，按 source_id 取一行作为该流的**常数复数旋转**
叠乘到位置 RoPE 上。`source_id=0`（target/clean）→ `vid=None` = 单位元，退化为纯框架 RoPE。
source=1、refs=2,3,…（dense 与流式分配一致）。

### 2.3 dense ↔ 流式 一致性（已数值验证）
- dense：source/clean/noisy 各用 `fr[0][:f]` → 位置 0..20；source 乘 `vid[1]`，target 不乘。
- 流式：`edit_causal_inference.py` 中 `fs = blk*nfpb` 是**块首帧索引**，`rope_start_frame=fs` →
  source 块 N 与 target 块 N 都拿到位置 N；refs 用 `rope_start_frame=0`（位置 0）。

校验结果：
```
(1) vid=None  dense==framework : True | stream==framework: True
(2) source_id dense==streaming : True | max diff 0.0
(3) q(tgt f2)·k(src f1) dense=1372.6950 stream=1372.6950 equal? True
```
(3) 说明 target↔source 的相对位置（含 source_id 相位）在训练与推理下数值完全相同。

## 3. 推理时"没有 target gt token"怎么办

流式推理逐块生成，"历史"= 模型**自己已生成的帧**，存在 `tgt_kv_cache`。
`edit_causal_inference.py` 每个块 N 三步：

1. **prefill source 块 N** → 写入 cond cache（source_id=1，位置 N）。
2. **few-step 去噪 target 块 N**（noisy 当 query；对应训练 noisy 流）。
3. **context refresh**：把生成的 `denoised` 在 `context_noise`（≈干净）下再跑一次，
   把 K/V 写回 tgt cache 第 N 槽 —— 这就是训练里"clean(gt) 帧 N"的等价物（来源换成自生成）。

对应关系：

| | 训练 clean 流 | 推理 tgt_cache |
|---|---|---|
| 角色 | 帧 i 的干净历史 | 自生成的帧 i（refresh 写入） |
| RoPE 位置 | i | i（`rope_start_frame`） |
| source_id | 0（恒等） | 0（恒等） |

KV-cache 存的是**已 RoPE 的 K**；当前 query 块 N 用位置 N 去和 cache 里位置 0..N-1 的 K 做注意力。
RoPE 是相对位置编码（score 只和 N-j 有关），所以训练"noisy 帧 N 看 clean 帧 j<N"与
推理"query 块 N 看 cache 帧 j<N"的几何逐位相同。

**结论**：训练的 `[source|refs|clean|noisy]` 单次并行前向，推理时塌缩成
`两个 cache（cond=refs+source；tgt=自生成历史）+ 当前 query 块`；clean(gt) 不是消失，而是被
cache 顶替，RoPE 位置完全对齐，不存在"少了 target token 导致 RoPE 错位"的问题。
